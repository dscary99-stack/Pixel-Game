# ตาราง EXP ผู้เล่น Lv1–200 — Classic Challenge v1

วันที่: 3 ตุลาคม 2026  
สถานะ: **PROVISIONAL — ข้อเสนอใหม่เพื่อทดลองบาลานซ์**  
ขอบเขต: Base Level ของผู้เล่น ไม่ใช่ Job EXP, Skill EXP, Bond หรือ EXP คู่ใจหลัง Rebirth

## ข้อเสนอหลัก

ตั้งเป้าให้เริ่มเล่นและทดลองทีมได้เร็ว แล้วค่อยเพิ่มเวลาต่อเลเวลอย่างต่อเนื่อง ผู้เล่นที่จัดทีม แก้ทางธาตุ และเลือกแผนที่ดีขึ้นจะเติบโตเร็วขึ้นจริง
Lv200ยังเป็นเพดานที่ยืนยันแล้ว ส่วน Class2ที่50 / Class3ที่120 / จุติเทพที่200 เป็นจุดอ้างอิงแบบร่าง P16 ในเอกสารหลัก
ตารางนี้ไม่เพิ่ม Energy, โควตาฟาร์มรวม, การลด EXP ตามชั่วโมงเล่น หรือ Premium EXP

## สมมติฐานของเวลา

- ตัวละครและทีมพร้อมล่าในพื้นที่ใกล้เลเวลตนเอง มีอุปกรณ์เหมาะสม แต่ไม่ใช่ทีมแต่งเต็มที่
- อ้างอิง **120 มอนสเตอร์ทั่วไปต่อชั่วโมง** ไม่ใช่120ไฟต์: เฉลี่ย3ตัวต่อไฟต์, รอบสู้รวมเดิน/เติมของ/พักเฉลี่ย90วินาที
- ไม่รวมโบนัส Party, Daily/Weekly, Elite/Boss หรือโบนัสจากกิจกรรม
- เป็นชั่วโมงล่าที่รวมเวลาระหว่างไฟต์ตามสมมติฐานแล้ว ไม่รวมยืนคุย จัดตลาด เดินสำรวจนาน ๆ หรือออฟไลน์
- Autoได้ EXPต่อเป้าหมายเท่าปกติ ความเร็วเก็บจริงต่างได้จากคุณภาพทีมและการตัดสินใจ ไม่ได้ถูกบังคับให้สู้ช้าลง
- ค่า120ตัว/ชั่วโมงนี้เป็นสมมติฐานใหม่สำหรับตารางEXP ไม่ใช่ผลทดสอบ และไม่ใช้แทนตัวอย่างความเร็วล่าในตารางเศรษฐกิจเดิมโดยอัตโนมัติ
- ทุกตัวเลขเวลาต้องปรับเมื่อได้ข้อมูลเกมจริง โดยเฉพาะต้นเกมที่จำนวนคู่ใจ/ศัตรูต่อไฟต์ยังน้อย

ภายใต้สมมติฐานนี้: ถึง **Lv50 = 13.1 ชั่วโมง**, **Lv120 = 135.5 ชั่วโมง**, **Lv200 = 850.8 ชั่วโมง** และต้องมี EXPสะสมรวม **5,465,771,910**

## 3. สูตรสร้างตาราง

ใช้การออกแบบจากเวลาเป้าหมาย แล้วคำนวณ EXPที่ต้องใช้ ไม่เลือกเลขEXPใหญ่เพียงอย่างเดียว

`L` = เลเวลผู้เล่นปัจจุบันที่กำลังเก็บไป L+1; ใช้ได้1–199  
`M` = เลเวลป่าคงที่ของชนิดมอนสเตอร์ ใช้คำนวณงบEXPของตัวอย่างมอนสเตอร์เท่านั้น

```text
ReferenceNormalXP(M) = 20 + 6*M + 2*M*M
ReferenceKillsPerMinute = 2
RequiredXP(L) = round_half_up_to_10(TargetMinutes(L) * 2 * ReferenceNormalXP(L))
CumulativeXP(1) = 0
CumulativeXP(L+1) = CumulativeXP(L) + RequiredXP(L)
```

TargetMinutes(L) ใช้ linear interpolation ระหว่าง anchorติดกันดังตาราง ไม่ปัดเวลาก่อนคำนวณEXP
`round_half_up_to_10(x)` = `10 * floor(x/10 + 0.5)` สำหรับค่าบวก ปัดครึ่งขึ้นอย่างสม่ำเสมอ
เมื่อปัดEXP เวลาอ้างอิงจริงจึงต่างจากเป้าเล็กน้อย โดยเฉพาะLv1

| ---: | ---: |
| 1 | 1 |
| 10 | 4 |
| 25 | 12 |
| 49 | 40 |
| 50 | 41 |
| 80 | 90 |
| 119 | 180 |
| 120 | 185 |
| 150 | 360 |
| 170 | 600 |
| 190 | 900 |

มีanchor49/50และ119/120เพื่อให้เส้นต่อเนื่อง ไม่มีเพิ่มEXPหลายเท่าทันทีเมื่อเปลี่ยนอาชีพ
การปรับความยากเฉพาะช่วงให้แก้เวลาanchorแล้วสร้างตารางใหม่ ไม่แก้200แถวด้วยมือ

**EXPมอนสเตอร์ต้องคงตามspecies**: สูตรนี้เป็นงบตั้งต้นให้คอนเทนต์แต่ละชนิด ไม่ใช่สูตรเปลี่ยนรางวัลมอนตัวเดิมตามเลเวลผู้เล่นหรือแผนที่
ออกแบบ species XPจริงโดยพิจารณาHP, ความอันตราย, พฤติกรรม, จำนวนในฝูง และเวลาเดินถึง; กลุ่มระดับเดียวกันไม่จำเป็นได้EXPเท่ากันทุกชนิด
ไม่ต้องเพิ่มโทษEXPมอนเลเวลต่ำในต้นแบบ: EXPคงเดิมก็มีสัดส่วนเล็กลงเองเมื่อผู้เล่นต้องการมากขึ้น ผู้เล่นยังกลับล่าSigil/วัสดุเก่าได้

## 5. Daily, Weekly, Boss และการลดความจำเจ

เสนอให้EXPจากเควสปกติเทียบกับเวลาฟาร์มสั้น ๆ ไม่จ่ายเป็นเปอร์เซ็นต์EXPที่ต้องใช้ต่อเลเวล เพราะปลายเกมจะเกิดแรงจูงใจเก็บรางวัลรอขึ้นช่วงแพง
ค่าเริ่มทดลอง: Dailyแต่ละงานให้เทียบ5นาทีล่า, Weeklyแต่ละงานเทียบ20นาทีล่า อ้างอิงระดับความยากงานที่ตรึงเมื่อมอบหมาย ไม่อัปมูลค่าเพียงเพราะผู้รับขึ้นเลเวลก่อนกดรับ
ตัวอย่าง `DailyXP = round10(5 * 2 * ReferenceNormalXP(questDifficultyLevel))`; งานที่ใช้เวลาต่างกันต้องปรับรายงาน
นี่เป็นโบนัสเพิ่มเติมจากkill/itemที่ทำระหว่างเควส; จำนวนเควสตามP13ยังเป็นข้อเสนอและไม่จำกัดการฟาร์มทั่วไป

Boss/Eliteควรให้EXPตามเวลาและความเสี่ยงจริง ไม่มีตั้งคูณสิบเพียงเพราะเป็นBossโดยไม่เทียบเวลาฆ่า
ตั้งเกณฑ์ทดลองEXPต่อชั่วโมงของพื้นที่ระดับเดียวกันต่างกันไม่เกินประมาณ20–25%เมื่อใช้ทีมเหมาะกับพื้นที่ ก่อนนับเป้าหมายlootต่างกัน
สนามที่ล่าเพื่อเงินหรือของหายากยอมให้EXPน้อยกว่าได้ ต้องบอกผู้เล่นชัด ไม่บังคับทุกmapเก่งทุกด้านเท่ากัน
ชนะบอสเพิ่มทางเลือกloot/recipe/วิธีจัดทีม ไม่แจกข้ามสิบเลเวลโดยไม่มีงบEXP

ช่วง170–200ให้มีความคืบหน้าระหว่างรอขึ้นเลเวล: Skill, Bond, อุปกรณ์, Sigil, collectionและพื้นที่ใหม่ ไม่ผูกทุกอย่างกับการขึ้นเลเวลครั้งถัดไป
ความยากการต่อสู้ต้องมาจากรูปแบบศัตรูและการเลือกทีมด้วย ตารางEXPเพียงอย่างเดียวเพิ่มเวลาฟาร์ม ไม่ได้สร้างความท้าทายเชิงกลยุทธ์

## 6. คู่ใจและ Rebirth

ตารางนี้ใช้กับผู้เล่นเท่านั้น ส่วนคู่ใจต้องทำตารางแยกเพื่อรองรับการจับใหม่Lv1และการเปลี่ยนทีมบ่อย
คงกฎ: คู่ใจเข้าทีมสูงสุด5ชนิดไม่ซ้ำ, storageไม่รับEXPเอง, จับใหม่Lv1 และRebirthเมื่อถึงเลเวลสูงสุดตามกฎที่จะตัดสิน
ห้ามนำตาราง851ชั่วโมงไปใช้ซ้ำกับคู่ใจทุกตัว/ทุกRebirthโดยอัตโนมัติ เพราะจะทำให้ทดลองทีมใหม่ลำบากและขัดจุดขายความหลากหลาย
ก่อนกำหนดเวลาคู่ใจให้สรุป: EXPต่อสมาชิก/การอุ้มตัวใหม่, effective-levelของคู่ใจที่สูงกว่าผู้เล่น, เลเวลสูงสุดคู่ใจ และจำนวนRebirth/เส้นทางเร่งกลับที่ไม่ซื้อด้วยPremium
ค่าTrade+30 / effective-level+5 / Rebirth3ครั้งยังOPENตามทะเบียนเดิม ตารางนี้ไม่ได้อนุมัติแทน

## 7. กติกาเก็บ EXP และเกณฑ์ตรวจ

- EXPสะสมเป็นจำนวนเต็ม64บิต เพราะยอดรวมตารางนี้เกิน4,294,967,295; สำหรับJSON/JavaScript ยอดปัจจุบันยังอยู่ในช่วงจำนวนเต็มแม่นยำ แต่ห้ามใช้bitwise32บิต
- คำนวณและบันทึกบนserver; reward eventเดิมretryต้องไม่แจกซ้ำ
- ได้EXPเกินหนึ่งเลเวลให้ข้ามหลายเลเวลได้และเก็บเศษ ไม่ทำEXPหายทุกครั้งที่ขึ้นเลเวล
- เลเวลถึงเกณฑ์เปลี่ยนอาชีพยังสะสมEXPต่อได้แม้ยังไม่ทำบททดสอบ; ไม่เปลี่ยนอาชีพเองและไม่แจกแต้มซ้ำเมื่อทำทีหลัง
- ที่Lv200ใช้`xp_to_next = null`; ไม่ใช้0เป็นเงื่อนไขwhileจนเลเวลเกิน200
- ข้อเสนอ ณcap: เก็บplayer progressionที่เพดาน ไม่สะสมล่วงหน้าเพื่อLv201; loot/เงิน/กิจกรรมอื่นยังทำต่อได้ตามปกติ นี่ไม่ใช่โควตาฟาร์มรางวัลรวม
- ต้นแบบนี้เสนอไม่มีEXPหายเมื่อตาย; ความเสียหายเป็นเวลาและไอเทมที่ใช้แล้ว หากเพิ่มdeath penaltyต้องคำนวณเวลาใหม่ ไม่ซ่อนรวมไว้
- KillกับCaptureต้องใช้entitlementที่ไม่ซ้ำและยึดcapture reward policyเดิมที่ยังเป็นข้อเสนอ ไม่รับEXPสองครั้งจากเป้าหมายเดียว
- ยืนยันค่าบวก200แถว, 199ช่วงขึ้นเลเวล, ค่าEXPเพิ่มต่อเนื่อง, ผลรวมตรง, ขอบ50/120/200 และไม่มี201
- ทดสอบXP/timeกับทีมอย่างน้อยtank/sustain/burst/control ทั้งManual/Autoที่Lv25/50/80/120/150/170/190/199 รวมเดินเติมของจริง
- หากผู้เล่นขึ้นเร็วเกินเป้าให้ตรวจแหล่งEXP/ฝูง/การอุ้ม/คอมโบผิดปกติก่อน ไม่เพิ่มEXPทั้งตารางเพื่อชดเชยช่องโหว่จุดเดียว

การตรวจที่ทำกับฉบับนี้: ตรวจจำนวนแถว, monotonic EXP, cumulative sums, rounding และboundaryด้วยสคริปต์ ผ่านทั้งหมด
ยังไม่ได้ทำplaytestหรือsimulationการต่อสู้จริง จึงไม่อ้างว่า851ชั่วโมงคือเวลาที่เกิดขึ้นแน่นอน

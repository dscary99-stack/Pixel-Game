# แนวภาพและสัญญาส่งต่องานแอนิเมชัน — Preproduction v1

วันที่ 7 ตุลาคม 2026 · ผู้ทำภาพ: Codex · ผู้รับงานเชื่อมเกม: Claude

**สถานะ: ข้อเสนอสำหรับต้นแบบภาพ ยังไม่ใช่มาตรฐานที่อนุมัติหรือ asset พร้อมเข้าเกม**

อ่าน `START_HERE.md` และ `GAME_DESIGN_MASTER.md` บท 10 ประกอบแล้ว เอกสารนี้แยกงานภาพให้ทำคู่ขนานกับระบบเกมได้ โดยไม่เปลี่ยนกติกาจับคู่ใจหรือโค้ดเกม

## 1. ทิศทางจากภาพที่ผู้ใช้ส่ง

- Monster: ขอบน้ำเงินม่วงเกือบดำ รูปทรงอ่านง่าย พิกเซลก้อนค่อนข้างใหญ่ เงาเป็นกลุ่มสีชัด ไฮไลต์สว่าง ตาเด่น และบุคลิกแฟนตาซี ทั้งน่ารักและน่ากลัวได้
- Item: ตัวอย่างเสื้อยีนส์และจอยเป็นภาพ 72×72 มีรายละเอียดละเอียดกว่า monster แต่ยังใช้ขอบเข้มและเงาเป็นกลุ่ม การมองเห็นเมื่อย่อใน UI สำคัญกว่าจำนวนรายละเอียด
- รักษาความหนาแน่นพิกเซลให้คงที่ภายใน asset ประเภทเดียวกัน ไม่เติม blur, soft glow หรือเส้นโค้งที่หลุดกริดในไฟล์ production
- พื้นสีและ texture ในภาพ monster เป็นส่วนของภาพอ้างอิง ไฟล์ sprite จริงใช้ PNG โปร่งใส แยกเงาเท้าและ VFX
- ภาพอ้างอิงกำหนดสไตล์ ไม่ได้ยืนยันชื่อ species, ธาตุ, rarity หรือ stat ของตัวละครใหม่

## 2. งานภาพชุดแรก

### ข้อแก้ไขมุมมองหลังอ่านเอกสารซ้ำ (7 ต.ค. 2026)

ตรวจบท10 ของ Game Design Master ทั้งไฟล์ local และสาขา `claude/project-thread-ektp0t` แล้ว: โลกกำหนดแนวทดลอง **2D 3/4 top-oblique, fixed camera** และสนามต่อสู้เป็น **arena oblique** จึงต้องวาด sprite 2D ให้เข้ากับมุมมองเฉียงจากด้านบนและพื้นสนามที่มีความลึก (เรียกบรรยากาศว่า 2.5D ได้) ไม่ได้กำหนดให้ทำโมเดล 3D หรือหมุนกล้อง และยังไม่ได้ล็อกองศากล้องหรือกริด isometric 2:1

- **โลก:** เห็นด้านบนและด้านข้างของตัว/เปลือกพออ่านมุมกล้องได้ ยึดเท้ากับพื้นเดียวกัน ภาพเดิน4ทิศรองรับการเคลื่อน8ทิศ; renderer ทำ y-depth sorting และ occlusion ตามเอกสาร
- **สนามต่อสู้:** ฝ่ายผู้เล่นซ้าย ศัตรูขวา หันเข้าหาคู่ต่อสู้ในสนามเฉียง ต้องตรวจท่าฝั่งเพื่อนและฝั่งศัตรู ลายเกลียวเปลือก/อวัยวะที่ไม่สมมาตรห้าม flip โดยไม่ตรวจ
- **ไอเทมในกระเป๋า / Sigil / ไอคอน:** เป็นภาพ2Dตามคำสั่งผู้ใช้ล่าสุด วาดเฉียงเพื่อให้เห็นรูปทรงได้ แต่ไม่ต้องใช้มุมกล้องเดียวกับโลกหรือสร้างภาพ4ทิศ ทั้งนี้อุปกรณ์ที่แสดงบนร่างตัวละครเป็น sprite layer อีกชุด ไม่ใช่ไอคอนในกระเป๋า
- **ภาพหอย concept v2 ที่สร้างแล้ว:** ใช้อ้างอิงสี รูปทรงและบุคลิกเท่านั้น ยังไม่มีหลักฐานว่ามุมกล้องและสัดส่วนเข้ากับพื้นสนาม จึงยังไม่ใช้เป็นแม่แบบ animation ที่ล็อกแล้ว
- **proof ถัดไป:** ทำหอยในมุม top-oblique บนพื้นทดลองที่เห็นตำแหน่งสัมผัสพื้น ตรวจคู่กับ player/สนามก่อน แล้วจึงล็อกมุมและทำ idle; แยกเงาออกจากไฟล์ sprite ที่ส่งจริง

อ้างอิง: [Game Design Master บท10](https://github.com/dscary99-stack/Pixel-Game/blob/claude/project-thread-ektp0t/docs/GAME_DESIGN_MASTER.md#chapter-10) มุมกล้องละเอียด ขนาด และจำนวนเฟรมยังเป็น PROVISIONAL ตามเอกสารหลัก

1. **Lantern Snail / หอยทากโคมไฟ:** ภาพแนวคิด monster คู่ใจ ตัวเล็ก เปลือกเป็นโคมแฟนตาซี เน้นรูปทรงจำง่ายและพื้นที่สำหรับแอนิเมชันหนวด/แสง
2. **Shell Capture Charm / เครื่องจับรูปเปลือกหอย:** ภาพแนวคิด item ในภาษาภาพเดียวกัน เป็นตัวอย่างหน้าตาเท่านั้น ไม่กำหนดสูตรจับ คุณภาพหรือราคาสินค้าแทนเอกสารระบบ

ชุดนี้เป็น concept สำหรับตรวจสไตล์ก่อน ยังไม่มีชุดเฟรม animation, sprite sheet หรือผลทดสอบใน Phaser ภาพที่สร้างขนาดใหญ่ไม่ถือว่าเป็น native pixel-grid asset เพียงเพราะมีลักษณะเป็น pixel art

## 3. ขนาดและกริดที่เสนอ

| ใช้งาน | ข้อเสนอสำหรับ proof | สถานะเทียบเอกสารหลัก |
| --- | --- | --- |
| Monster ในสนามต่อสู้ | กรอบ logical 96×96 px | ทดลองเฉพาะต้นแบบนี้; เอกสารหลักเสนอ standard 64×64 และ large 96×96 |
| Monster บนแผนที่ | กรอบ 64×64 px, ภาพ 4 ทิศ | ต้องตรวจร่วมกับ player และพื้นแผนที่ก่อนผลิตจำนวนมาก |
| Item ต้นแบบ | 72×72 px | ตามตัวอย่างใหม่ของผู้ใช้; เอกสารหลักเสนอ item 32×32 จึงต้องตรวจ UI ก่อนเปลี่ยนมาตรฐาน |

กรอบคือพื้นที่ว่างสำหรับการเคลื่อนไหว ไม่ใช่บังคับให้ตัวละครเต็มทุกพิกเซล ห้ามย่อภาพ concept แล้วประกาศว่าผ่านกริดโดยไม่ตรวจ ขนาด export ต้องเป็นขนาด logical จริง; ภาพพรีวิวขยายด้วย nearest-neighbor เท่านั้น

ตั้งจุดอ้างอิงที่กึ่งกลางล่างของกรอบ (`origin: [0.5, 1]`) และกำหนดตำแหน่งพื้นร่วมของทุกเฟรมไว้ใน metadata ตัวลอยใช้ตำแหน่งพื้นเสมือนเดียวกันพร้อมเงาแยก ห้าม trim แต่ละเฟรมจนตำแหน่งตัวสั่น หากทำ atlas แบบ trim ต้องรักษา source size และ offset ครบ

## 4. ลำดับทดลองแอนิเมชัน

| ชุด | เฟรม | เวลา/การเล่นที่เสนอ | สิ่งที่ต้องตรวจ |
| --- | --- | --- | --- |
| Idle ชุดแรก | 4 | 6 fps, loop | หนวด/ตัวขยับเล็กน้อย จุดวางเท้านิ่ง รอยต่อวนลื่น |
| Walk บนแผนที่ | 4 ต่อทิศ × 4 ทิศ | 8 fps, loop | down/left/right/up; ให้ movement 8 ทิศเลือกภาพใกล้สุด |
| Attack สนามต่อสู้ | 6 | 10 fps, เล่นครั้งเดียว | เตรียม → ลงน้ำหนัก → กลับท่า; ระบุ hit frame หลังเห็นเฟรมจริง |
| Hurt | 2 | 8 fps, เล่นครั้งเดียว | อ่านออกแต่ไม่หลุด anchor |
| KO | 4 | 8 fps, ค้างเฟรมสุดท้าย | รูปทรงไม่สับสนกับ idle และไม่วนเอง |

นี่เป็นข้อเสนอประหยัดขอบเขตสำหรับ proof โดยเฉพาะ idle 6 fps และ walk 4 เฟรม ต่างจากค่าทดลองในเอกสารหลักที่เสนอ 8–12 fps และ walk 6–8 เฟรม หากดูสะดุดให้เพิ่มเฟรมก่อนขยายการผลิต แอนิเมชันสนามต่อสู้เริ่มจากทิศเดียวที่เลือกใน proof ก่อน ไม่ได้สัญญาว่าทุก action มีครบ 4 ทิศ

ไม่ flip ซ้าย/ขวาอัตโนมัติเมื่อทำให้ลายหรืออุปกรณ์ผิดฝั่ง การเล่นภาพและ hit frame เป็นการนำเสนอผลจาก server ไม่ใช่ตัวตัดสินดาเมจหรือความเร็วฟาร์ม

## 5. ไฟล์ส่งต่อและ manifest

ชื่อเสนอ: `mon_lantern_snail_battle_idle_v001.png`, `mon_lantern_snail_world_walk_down_v001.png`, `item_shell_capture_charm_v001.png` แยก `concept/`, `sprites/`, `previews/` และ `metadata/` เมื่อเริ่มผลิตจริง ห้ามใส่ concept ใน path ที่ loader คาดว่าเป็น sprite สำเร็จ

ส่ง PNG RGBA พร้อม manifest ต่อ asset ที่ระบุ:

- `assetId`, `version`, `status` (`concept`, `grid_ready`, `animation_verified`), ไฟล์ต้นทางและใบอ้างอิง
- `frameWidth`, `frameHeight`, `columns`, `rows`, `frameCount`, `padding`, `spacing`; สำหรับ sheet กำหนดลำดับ row-major ชัดเจน
- `origin`, `groundOffset`, `directions`, `layers`, `shadowAsset`; atlas ต้องมี source size และ trim offsets
- `animations`: ชื่อ state, ทิศ, frame indices, duration ต่อเฟรมหรือ fps, loop และ hit frame ที่ตรวจแล้ว
- ขอบเขตสี/palette variants, การ flip ที่อนุญาต, ขนาดแสดงผลที่ผ่าน visual proof

ห้ามใส่ manifest ว่า `animation_verified` จนผ่าน QA จริง และยังไม่สร้าง manifest อ้างถึงไฟล์ที่ไม่มีในชุด concept นี้

## 6. เกณฑ์รับงานก่อน Claude เชื่อมเกม

- เปิดดูขนาด 1× และ 4× แบบ nearest: ขอบคม ไม่มีพิกเซลหลง ไม่มี halo สีพื้นหรือส่วนโปร่งใสผิด
- อ่าน silhouette ได้บนพื้นสว่างและมืด; item ยังแยกชนิดออกในขนาด UI จริง โดยเฉพาะหากลดจาก 72 เป็น 32 px
- ทุกเฟรมคงจำนวนอวัยวะ ตำแหน่งลาย ขนาดตา เปลือก และทิศแสง ไม่มีส่วนหายหรือรายละเอียดงอก
- เล่น loop จริงเพื่อตรวจเฟรมท้ายต่อเฟรมแรก; ตรวจ ground anchor, พื้นที่ขอบกรอบ และส่วนยื่นทุกท่า
- ตรวจ sheet ตาม manifest: ไม่มีเฟรมซ้อน/ถูกตัด จำนวนเฟรมและดัชนีตรงกัน เงาไม่ขยับผิดจังหวะ
- ใน Phaser ใช้ nearest filtering และ pixel snapping ตามกล้อง ตรวจฉากสนามต่อสู้/แผนที่และมือถือแนวนอนที่ขนาดจริงก่อนล็อกมาตรฐาน

## 7. แบ่งงานคู่ขนาน

**Codex:** concept → เก็บกริด → เฟรมและพรีวิว → QA → ส่งไฟล์พร้อม metadata ตามขอบเขตที่ผู้ใช้มอบหมาย

**Claude:** ตรวจสัญญา asset กับ renderer ปัจจุบัน เตรียม loader/animation mapping ด้วย placeholder และเชื่อม state หลังได้รับชุดที่ตรวจแล้ว เลือกตำแหน่งไฟล์จริงใน repo ร่วมกับมาตรฐานเดิม

ก่อนรวมงานให้ตกลงเฉพาะขนาดที่ผ่าน proof, naming และ ownership ของไฟล์ ไม่แก้ไฟล์เดียวกันพร้อมกัน เอกสารนี้เป็นการส่งต่องานด้วยไฟล์ ยังไม่ได้ส่งข้อความให้ Claude หรือแก้ implementation
